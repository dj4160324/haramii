# 하라미 병동 근무표 v0.12.7

Windows에서는 ZIP 전체를 같은 폴더에 풀고 START-WINDOWS.cmd를 실행합니다. 브라우저가 열리면 기존 JSON을 불러오거나 직원과 조건을 입력한 뒤 근무표 생성을 누릅니다. 프로그램을 사용하는 동안 실행 창을 열어 두세요. macOS 또는 Linux에서는 이 폴더에서 `python3 start.py`를 실행합니다. 생성·저장·불러오기는 관리자 PC의 브라우저에서 수행합니다. 정상적으로 고립된 브라우저 환경에서는 실제 WASM 최적화가 실행됩니다. 웹 호스팅용 파일은 dist/에 있습니다. 사이트 루트에서 제공하고 포함된 _headers 또는 그에 대응하는 격리 헤더를 적용하세요.

## 편성 정책

브라우저의 기준은 GPT Work v0.12.6-burden입니다. 날짜별 신규·프리셉터 연동, 개인별 실제 이력에 근거한 누적 부담, 원시 셀 감사와 최종 후보 순위를 이어받았습니다. Codex 테스트 1에서 사용한 일반 교대 직원의 7일 구간별 N 쏠림 악화 방지를 웹 최적화와 원시 감사에 적용했습니다. 이미 N이 4회 이상인 구간도 시작안보다 늘릴 수 없습니다. 보호 OFF 수를 직원별로 재검사하며, 회차 시작 이틀 전 종료된 연속 N도 탐색 모델의 회복 조건에 포함합니다.

7일 연속근무를 금지합니다. 7일 중 6일 근무는 직원별 반복과 전체 횟수를 줄이는 목표입니다. 당회 주말 OFF 차이 최대 2일을 유지합니다. 누적 주말 OFF는 최근 3개월 목표로 관리하며, 반복 부담 감소를 우선할 때 차이가 커질 수 있습니다. 최종 후보의 새 회복 확인 경고는 계속 제외합니다. 알려진 야간 회복 위반은 계획 확정 저장에서도 다시 검사합니다. 직전 이력이 부족한 경우에는 경고가 표시되므로 관리자가 실제 이력을 보충해야 합니다.

통합본은 한 개의 웹 프로그램입니다. 일상 사용에 Python 최적화기나 개발용 테스트 설치는 필요하지 않습니다. 구버전 Windows의 PowerShell 실행 정책과 조직의 브라우저 제한은 현장 환경에서 확인해야 합니다.

## 검증 재현

`node checks/regression.cjs`는 배포 HTML과 JS에 대해 경계·교육·보호 OFF·N 창 검사를 수행합니다. Chromium과 Python Playwright를 갖춘 Linux에서 `python3 checks/browser.py`로 생성 버튼과 저장 후 다시 열기를 검사할 수 있습니다. Codex 복구 원본의 validation/이 있는 프로젝트 루트를 인수로 넘기면 `node checks/replay.cjs 경로`와 `python3 checks/ward-browser.py 경로`로 22명 자료를 검증할 수 있습니다. 측정 결과는 TEST-REPORT.md에 있습니다.
